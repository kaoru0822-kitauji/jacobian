# v0.4 specification: research memory

- Status: Provisional
- Theme: Learn from experiments without confusing memory with proof

## 1. Entry gate

The engine must have a sufficiently diverse corpus of verified successes,
verified failures, and unverified runs to evaluate retrieval quality.

## 2. New tools

### `memory.search`

Retrieve prior records using independently selectable indexes:

- natural-language text;
- normalized formula structure;
- quantifier skeleton;
- exact metadata;
- canonical object hash;
- substructure or motif;
- witness and failure type;
- proof or certificate type;
- ancestry;
- temporal cutoff.

Every result returns its trust, review, source, and availability labels.

### `abstraction.extract`

Suggest an interpretable abstraction for one or more concrete artifacts, such
as a clique, odd cycle, cut, parity condition, or invariant.

The result is a hypothesis artifact with supporting examples. It is never
verified by this tool.

### `episode.compare`

Compare failed experiments, cluster their verified witnesses, and propose a
recurring obstruction or possible no-go lemma.

### `certificate.simplify`

Minimize a certificate according to format-specific objectives while replaying
the authorized checker after every accepted change.

## 3. Record lifecycle

```text
raw run
    → canonical deduplication
    → experiment record
    → verification and review
    → curated knowledge record
```

Trust labels:

```text
UNVERIFIED
WITNESS_VERIFIED
CERTIFICATE_VERIFIED
FORMALLY_VERIFIED
HUMAN_REVIEWED
RETRACTED
```

Retention policies prevent duplicate or low-value runs from overwhelming
storage and retrieval.

## 4. Temporal evaluation

Records preserve:

- source publication date;
- first-known date;
- ingestion date;
- verification date;
- review date.

Historical benchmarks may impose a knowledge cutoff so retrieval cannot use a
later solution.

## 5. Exit gate

v0.4 is complete when:

- trust labels survive every retrieval path;
- temporal cutoffs are enforced;
- retrieval improves a held-out search or repair task;
- abstraction tools do not silently promote hypotheses to verified records;
- duplicate and poisoned-run tests do not dominate results.
